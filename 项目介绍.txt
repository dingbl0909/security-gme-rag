项目简介：
在依图从事安防方向大模型应用开发期间，我负责将设备接入、布控告警、项目部署、故障排查等知识统一沉淀到一个可检索、可追溯、可问答的多模态知识库中。安防知识不仅存在于纯文本手册，也大量存在于 PDF 部署文档、接口说明、截图、告警时间线图片和历史案例中。传统关键词检索难以同时理解文本、图片以及图文组合问题，因此我基于多模态嵌入、混合检索、上下文记忆与 LangGraph 工作流，设计了一套面向安防业务的私有化多模态 RAG 系统，用于支撑研发、实施和运维团队的问题定位与辅助决策。

核心内容：

多模态知识组织与 Any-to-Any 检索：
将设备接入手册、告警处置规范、部署文档、接口说明、截图统一抽象为文本、图片和图文对三类知识单元。系统支持文搜图、图搜文和图文联合检索，使用户既可以基于故障描述检索相关截图，也可以基于图片反查相关知识和处置建议。

非结构化文档解析与版面保留：
基于 Dots.OCR 对 PDF、PPT、Word、HTML 等非结构化资料做解析，并通过 vLLM 在私有化算力环境中部署解析服务。解析时保留标题层级、段落结构、表格标签和图片 Base64 信息；对于截图和扫描件，补充 OCR 文本，作为后续多模态索引构建的统一输入。

章节分块 + SemanticChunker：
针对部署手册、接口说明和故障案例中常见的跨页表格、长段落和图文混排内容，先按章节标题和段落做粗粒度切分，再对超长文本使用 SemanticChunker 做二次语义切分，减少表格、图片说明和上下文之间的语义断裂。对于图片块，结合相邻文本生成图片语义描述，保证图片和文本可以进入同一向量空间。

基于 GME 的统一多模态向量空间：
采用 SentenceTransformers 私有化部署的 iic/gme-Qwen2-VL-7B-Instruct 作为核心多模态嵌入模型，对文本、图片和图文对生成统一稠密向量；同时基于 BM25 构建稀疏检索能力。Milvus 中维护 Dense / Sparse 双索引，稀疏侧采用 DAAT 倒排检索策略并调节 BM25 k1/b 参数，稠密侧使用 HNSW 并设置 M=30、efConstruction=64，在召回精度和查询性能之间取得平衡。

上下文工程与长期记忆：
使用 Redis 保存短期会话记忆和上下文摘要，降低重复检索带来的时延；同时将多轮问答中的关键结论、人工反馈和处置建议异步写回 Milvus 上下文集合，作为长期语义记忆。这样既能维持当前会话一致性，也能让系统利用历史案例提升后续问答质量。

基于 LangGraph 的多模态问答工作流：
工作流包含输入识别、历史上下文检索、知识库检索、答案生成、结果评估和人工审批等节点。对于纯图片问题，优先进入图像检索链路；对于文本问题，优先从历史上下文和知识库中做混合检索；对于召回证据不足或答案不可靠的问题，触发 Query 改写、重新检索或人工审核。

Corrective RAG + Adaptive RAG 双层评估：
第一层对检索结果进行 Context Precision 和 Context Recall 评估，判断当前证据是否足够支撑回答，并在必要时触发 Query 改写；第二层在答案生成后基于 Response Relevancy 和 Faithfulness 评估回答与证据之间的一致性，从而降低安防业务中的幻觉率。

RAGAS 闭环与 Human-in-the-loop：
引入 RAGAS 对检索和回答质量做持续评测，形成优化闭环。对于多次纠偏后仍低于阈值的结果，系统通过 LangGraph 的 Human-in-the-loop 机制进入人工审核节点，由人工确认、驳回或补充说明后再从中断点恢复执行，以满足安防场景下对准确性和可控性的要求。
